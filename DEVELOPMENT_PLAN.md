# DEVELOPMENT PLAN

This plan is organized into phases. See the scope boundaries below for FYP vs. aspirational scope.

---

# FYP Core Scope — Phases 0–4 + Final Polish

These phases constitute the deliverable FYP project. Phases 0–4 must be completed. Phase 10 (Final Polish) applies to whatever has been implemented.

# Phase 0 — Documentation

- Create repository
- Create project documentation
- Define architecture
- Define MVP
- Define coding conventions
- Define initial data model

---

# Phase 1 — Project Foundation

## Goals

Create a functioning application shell.

Tasks:

- Initialize React Native/Expo
- Configure TypeScript
- Navigation
- Theme
- Basic components
- Backend
- Database
- Authentication
- Environment configuration
- Git workflow

Deliverable:

A user can register, log in, and reach the dashboard.

---

# Phase 2 — Curriculum

Tasks:

- Course model
- Module model
- Topic model
- Concept model
- Prerequisites
- Initial DSA curriculum
- Seed data

Deliverable:

User can browse the initial DSA curriculum.

---

# Phase 3 — First AI Tutor Vertical Slice

This is the most important milestone.

Implement:

```text
Choose concept
 ↓
Start tutor
 ↓
AI asks question
 ↓
Student responds
 ↓
AI evaluates
 ↓
Knowledge state updates
 ↓
AI asks next question
```

Do not proceed to advanced features until this works reliably.

---

# Phase 4 — Adaptive Tutoring

Implement:

- Prerequisite descent
- Adaptive difficulty
- Hint levels
- Multiple interaction types
- Student knowledge state
- Confidence
- Follow-up questions

---

# FYP Deliverable Checkpoint

After Phase 4, the project should demonstrate:

- A working mobile application with authentication
- Browsable DSA curriculum
- End-to-end adaptive tutoring with AI
- Prerequisite descent and knowledge state tracking
- Multiple interaction types
- Hint system

This constitutes a defensible FYP deliverable.

---

# Future / Aspirational Scope — Phases 5–9

These phases extend the platform beyond the core FYP deliverable. They should not be attempted until Phases 0–4 are complete and stable. They are documented here to preserve the product vision, not to imply immediate implementation.

# Development Rule

Each phase should produce a usable increment.

Avoid spending weeks building infrastructure without an end-to-end feature.

For FYP purposes, focus on Phases 0–4 + Final Polish.
